# Glossary — Platform Terminology

Definitions for terms used across Framehouse Hub code, docs, and team communication.

---

## Asset

See **Media**.

---

## Media / Asset

A photo or video file managed by the platform. Each Media document in Payload represents one original file plus its derived representations (WebP thumbnail, proxy, and full-size variants). The Payload `Media` collection owns the metadata; the actual bytes live either in the **Enclave** (local mode) or in **GCS** (cloud mode).

**Key fields:** `originalUrl`, `thumbnailUrl`, `proxyUrl`, `accessionId`, `storagePath`, `uploadBatchId`, `mimeType`, `status`.

**Status lifecycle:** `pending` → `processing` → `ready` (or `error`)

---

## Enclave

The local per-tenant directory tree where original media bytes are written in local development mode. Path structure:

```
public/media/tenants/{userId}/{domain}/{year}/{month}/{assetUUID}/original/{filename}
```

- `domain` is server-derived from MIME type (e.g., `photos`, `videos`, `documents`). Clients cannot override it.
- `assetUUID` is generated at write time by `writeOriginalToEnclave`.
- In cloud mode, GCS replaces the enclave; the path shape is the same but lives in the bucket.

The helper `buildStoragePath` in `src/lib/storage-paths.ts` is the single canonical builder for this path. Never hand-construct it.

---

## Accession ID

A human-readable archival identifier assigned to each Media document at ingest time. Format:

```
ACC-{YEAR}-{SEQUENCE}
```

Example: `ACC-2024-00147`

Generated by the `generateAccessionId` beforeChange hook. Provides a stable, sortable, human-friendly reference for assets beyond the internal UUID.

---

## Upload Batch

A logical group of assets ingested together in a single "Start Archival Ingest" action. One `UploadBatch` document is created per commit click in the upload UI (`commitStagedFiles`). Its ID is stamped on every `Media` document ingested in that batch via `uploadBatchId`.

Used for timeline / batch-history surfaces and for tracing which assets came in together.

---

## Session

An ingest session groups multiple upload batches around a **shoot** — a related set of creative work (e.g., all photos from a single shoot day). Sessions provide a higher-level organisational unit above the batch. Represented by the `Sessions` collection.

---

## Smart Collection

A dynamic, rule-based grouping of media assets. Unlike a manually curated collection, a Smart Collection is defined by filter criteria (e.g., tag, date range, MIME type, status) and its membership is computed at query time. Defined in the `SmartCollections` collection.

See [FRH-47 Smart Collections Spec](../FRH-47-smart-collections-spec.md) for the full rule engine design.

---

## Portfolio

A curated, section-based presentation of media assets created by a creative user and shared with clients. Portfolios are composed of layout sections, each containing a selection of assets. Clients access portfolios via review links without requiring an account.

Defined in the `Portfolios` collection. Client interactions are tracked via **Client Review Sessions**.

---

## Client Review Session

A stateless-tracked viewer session created when a client opens a portfolio review link. Tracks view time, comments, and download actions without requiring the client to create an account. Represented by the `PortfolioClientSessions` collection.

Related collections: `PortfolioClientReviews`, `PortfolioAssetComments`, `PortfolioDownloadLogs`.

---

## Go Worker

An external Go microservice responsible for generating WebP derivative images from original media files. It runs as a Cloud Run service in cloud environments, or locally via `./scripts/dev-with-worker.sh` on port 8080.

**Derivatives generated:** `small` WebP, `medium` WebP (via `cwebp`).

**Trigger path (cloud):** GCS object-finalize event → Eventarc → Go worker → `/api/media/process-callback`

**Trigger path (local):** `triggerLocalWorker` afterChange hook → detached fetch to `LOCAL_WORKER_URL`

Source: `scripts/worker/main.go`

---

## GCS

**Google Cloud Storage.** The primary cloud object store for media bytes in non-local environments. Each environment (dev, prod) has its own private bucket. Buckets enforce public-access prevention — all reads are via time-limited **Signed URLs**.

Dev bucket: `gs://framehouse-hub-dev` (region: `us-central1`)

---

## Eventarc

A GCP service that routes events from GCS to the Go worker. When a file is uploaded to the GCS bucket (object-finalize event), Eventarc delivers the event to the Cloud Run worker service, triggering derivative generation.

The Eventarc service agent requires `roles/storage.legacyBucketReader` on the bucket. The GCS service agent requires `roles/pubsub.publisher` at project scope. These are distinct service accounts — do not conflate them.

---

## Payload

The CMS framework at the core of Framehouse Hub. Payload v3 runs embedded inside the Next.js process — there is no separate CMS server. It provides:

- Collection and global definitions (schema, hooks, access control)
- The admin UI at `/admin`
- REST and GraphQL APIs auto-generated from collection config
- Auth (JWT, sessions, role-based access)

`src/payload.config.ts` is the single source of truth for all Payload configuration.

---

## Route Groups

Next.js App Router route groups used to partition the application:

| Group | Path | Purpose |
|---|---|---|
| `(app)` | `/`, `/learn`, `/company`, `/pricing`, etc. | Public-facing marketing and gallery site |
| `(dashboard)` | `/dashboard/...` | Authenticated user dashboard (upload, media library, portfolio builder) |
| `(payload)` | `/admin`, `/api/...` | Payload admin UI and its REST/GraphQL APIs |
| `(portfolio)` | Portfolio presentation routes | Client-facing immutable portfolio viewer |
| `(coming-soon)` | Coming soon holding page | Pre-launch holding routes |

All route groups are served by the same Next.js process.

---

## Signed URL

A time-limited GCS GET URL that grants temporary read access to a private object. Generated by the `signCloudUrls` afterRead hook using the Cloud Run runtime service account's `iam.serviceAccountTokenCreator` self-grant.

**TTL:** 1 hour

**Rule:** Never persist signed URLs in the database or client-side caches. The DB always stores the unsigned `https://storage.googleapis.com/{bucket}/{path}` form. Signed URLs are generated fresh on each read.

---

## SSE

**Server-Sent Events.** Used for real-time streaming of media processing status to the browser. The `/api/media/status-stream` endpoint pushes processing state updates as assets move through the ingest pipeline (`pending` → `processing` → `ready`).

A 3-second polling backstop runs alongside SSE in the `UploadProvider` to handle cases where the SSE connection silently drops (observed in CI).

---

## Neon

The serverless PostgreSQL provider used in cloud environments (dev and prod). Connection strings are stored in GCP Secret Manager. The Neon adapter automatically lowers the connection pool to 4 connections when a Neon connection string is detected.

Local development uses a Docker Postgres container instead.

---

## Creative

A user role with elevated permissions scoped to their own content. Creatives can:
- Upload and manage their own media assets
- Create and manage portfolios
- Organise assets into collections and sessions

Creatives cannot access other users' assets or the admin panel. Access control modules: `creativeOrAdmin`, `ownerOrAdmin`.

---

## Admin

The superuser role with full platform access. Admins can:
- Access all content across all users
- Manage users, roles, and system globals (Header, Footer, Pricing)
- Access the Payload admin UI at `/admin`
- View admin activity logs and diagnostic sessions

Access control module: `adminOnly`.

---

## Viewer

The default role assigned to new registered users. Viewers have read-only access to published content. They cannot upload, manage assets, or access the dashboard. Primarily used for client accounts or public-facing user registrations.

---

## Additional Terms

### Proxy URL

A medium-resolution WebP derivative (`proxyUrl`) generated by the Go worker. Used for gallery display where full resolution is unnecessary. Falls back to `thumbnailUrl` → `originalUrl` if not yet generated.

### Thumbnail URL

A small-resolution WebP derivative (`thumbnailUrl`) used for grid and card views. Generated alongside the proxy by the Go worker.

### Media URL Fallback Chain

The canonical order for resolving a displayable URL for a media asset in UI components:

```
media.thumbnailUrl || media.proxyUrl || media.originalUrl || media.url
```

`url` is a Payload-internal fallback and may point to a stale path. Prefer the explicit derivative fields.

### process-callback

The `/api/media/process-callback` API route. Called by the Go worker after derivative generation is complete. Authenticated with `PROCESSOR_CALLBACK_SECRET`. Updates the Media document with derivative URLs and sets status to `ready`.

### Library Folder

The root organisational folder in the Payload folders system, auto-created via the `/api/library-id` endpoint. All user-created folders nest under this root. Protected by `protectLibraryFolder` (prevents deletion) and `ensureFolderParenting` (enforces correct parent on move) hooks registered in `payload.config.ts`.
